# 스마트 건설 로보틱스 논문 리뷰 스튜디오

논문 PDF를 넣고 **연구 공백·방법론·결과**를 각각 심사하는 석·박사 논문 검토 워크스페이스입니다. 안전·대응 대책, 사례 비교, 기술·작업계획을 추가할 수 있습니다. 자율주행은 제외합니다.

[웹앱 열기](https://semifinal02-debug.github.io/literature-reivewers/) · [수정본 미리보기](https://semifinal02-debug.github.io/literature-reivewers/preview/) · [기존 장별 요청 도구](https://semifinal02-debug.github.io/literature-reivewers/chapters/)

## 직접 AI 분석 미리보기

`/preview/`에서는 **OpenAI API 키를 직접 입력**하고 PDF·심사 범위를 선택하면 앱 안에서 리뷰를 받을 수 있습니다. 브라우저가 OpenAI 공식 API에 직접 요청하므로 GitHub Pages만으로 사용하며 Vercel 배포는 필요하지 않습니다. GPT-4.1과 GPT-4.1 mini를 지원합니다. 진행 상태·부분 실패·실패한 범위만 재시도를 제공합니다.

[미리보기 사용·API 키 안내](docs/DIRECT-AI.md): **AI 리뷰 실행 → OpenAI API 키 입력 → 연결 확인 → 선택 범위 분석 시작**. 키는 현재 탭에서만 사용하고 새로고침하면 지워지며 작업 파일·브라우저 저장소·주소·로그에 저장하지 않습니다. API 요금은 ChatGPT 구독과 별도입니다. 키를 채팅이나 GitHub 파일에 넣지 마세요. 별도 서버 연결도 선택할 수 있습니다. 기본 `index.html`은 기존 ChatGPT 복사 방식이며 아래 사용 설명은 이 기본 앱 기준입니다.

API 제한 오류는 크레딧·예산 부족, 분당 요청·토큰 제한, 원인 미확인으로 구분합니다. 첫 요청이 제한되면 후속 범위는 **미실행**이며 자동으로 요청을 반복하지 않습니다. 추가 API 비용을 원하지 않으면 **현재 원고로 ChatGPT 요청 만들기**를 선택해 복사·응답 가져오기를 사용하세요. ChatGPT 계정의 사용 한도는 적용됩니다.

## 실제 리뷰 받기

1. **논문 & 연구 설정**에서 PDF를 선택하거나 본문을 붙여 넣습니다. 학위 수준·연구 유형·제공 범위·연구 질문을 설정합니다.
2. **심사 범위 선택**에서 필요한 리뷰어를 고릅니다. 1–2장은 공백·기여, 3장은 방법론, 4–5장은 결과·해석에 연결합니다. 범위별 6개 기준, 최대 36개를 검토합니다.
3. **AI 심사 요청 만들기**를 누르고 요청 전체를 ChatGPT의 새 대화에 붙여 넣습니다. 실제 AI 심사는 ChatGPT에서 실행합니다.
4. JSON 응답을 **ChatGPT 리뷰 연결**에 붙여 넣거나 파일로 가져옵니다. 앱이 원문 줄·인용을 대조하고 리뷰 보고서를 만듭니다.
5. 보고서에서 범위·평가 상태를 선택해 읽습니다. Major/Minor 의견, 수정 행동, 원문 근거, 결과 지표, 확인 질문을 보고 수정합니다. 수정 확인 체크와 보고서 Markdown·인쇄/PDF 저장을 지원합니다.

**예비 점검 실행**은 문구·보고 항목을 찾는 규칙 기반 도구입니다. 공백의 타당성, 방법론 적합성, 결론의 유의미함을 판정하는 AI 심사가 아닙니다. 예비 점검에서 학술적 평가 기준은 판단 보류로 표시합니다. **예시 논문으로 살펴보기**는 합성 원고로 이 흐름을 보여 줍니다. 실제 연구 결과가 아닙니다.

## 무엇을 평가하나요?

- **연구 공백·기여:** 제공 문헌에서 공백을 도출하는 논리, 문헌 선정 범위, 공백의 종류, 질문 연결, 기존 연구 대비 차이, 주장 범위.
- **방법론·연구 설계:** 질문–방법 적합성, 표본·데이터, 변수·지표, 비교·통제, 재현성·신뢰도, 타당성·윤리.
- **결과·유의미성:** 통계적 근거, 효과 크기·불확실성, 기술 성능, 현장·실무 의미, 강건성·민감도, 해석·일반화.
- **케이스스터디·비교:** 사례 선정, 출처 추적, 비교 조건, 삼각검증, 계획–실행 차이, 전이 가능성.
- **안전·대응 대책:** 위험원·노출, 위험 평가, 대책 연결, 효과 검증, 잔여 위험, 안전 주장 범위.
- **기술·작업계획:** 작업 능력·제약, 작업 분해·순서, 자원·공간, 인간–로봇 역할, 예외·복구·재계획, 성과 검증.

석사는 질문–방법–근거의 연결을, 박사는 독창적 기여·기존 연구와의 차이·일반화 범위까지 검토하도록 요청합니다. 정성적 사례 연구에 p값을 일률적으로 요구하지 않습니다. p값·효과 크기·기술 성능·현장 효용을 따로 평가하고 종합 점수나 게재 판정을 만들지 않습니다.

## 근거 확인과 제한

AI 응답의 `source_id`가 현재 원고·설정과 맞아야 보고서를 가져올 수 있습니다. 원고나 설정을 바꾸면 이전 결과를 닫습니다. 인용은 지정한 줄의 정확한 문자열과 비교합니다. 강점·보완 판정에 일치하는 인용이 없으면 판단 보류로 표시합니다. 누락된 평가 기준도 보류하고 알립니다. 이 확인은 **주장의 학술적 타당성, 수치의 정확성 또는 문헌의 존재를 검증한 것과 다릅니다**.

외부 문헌 검색, 원자료 통계 재검정, OCR은 수행하지 않습니다. 기본 앱은 ChatGPT 응답을 가져오며 미리보기는 OpenAI API를 직접 호출합니다. 제공 자료로 확인하지 못한 문헌 최신성·독창성을 확정하지 않도록 요청합니다. 일부 발췌에 없는 내용을 전체 논문의 결함으로 단정하지 않습니다. 학위 통과·게재·안전을 보증하지 않습니다.

## PDF와 작업 파일

PDF는 브라우저에서 읽고 원본을 서버에 업로드하지 않습니다. 최대 20MB·한 번에 100페이지·본문 25만 자이며 시작·끝 페이지를 선택할 수 있습니다. 번호는 PDF 파일의 첫 페이지부터 세는 순서입니다. `[PDF n페이지]` 표식과 원고 줄 번호를 함께 보존합니다. 표·수식·다단 편집·이미지는 원본과 대조하세요. 스캔 PDF는 OCR, 암호화 파일은 잠금 해제된 사본이 필요합니다. 실패 시 기존 원고를 유지합니다.

**작업 저장/열기**는 원고·설정·가져온 리뷰·수정 확인 상태를 JSON 파일에 보존합니다. 이 파일에는 논문 내용이 포함됩니다. 자동 저장·클라우드 저장·Supabase 저장은 없습니다. ChatGPT에 복사하거나 다운로드한 자료는 직접 보관하세요. 기존 장별 도구의 작업 파일은 별도 형식이며 `/chapters/`에서 사용합니다.

## 개발과 빌드

정적 웹앱이라 GitHub Pages에서 실행합니다. PDF.js 모듈·문자 매핑·글꼴은 HTML에 포함합니다. 미리보기의 직접 AI 심사에는 사용자 API 키가 필요하며 자체 서버는 필요하지 않습니다. 수정본만 빌드하려면 `python build_preview.py`를 사용하세요. 아래 `build_web.py`는 기본 앱까지 교체합니다.

```sh
python build_web.py
python -m http.server 8000 --bind 127.0.0.1
```

- `review_ui.html`: 새 화면 원본.
- `review_workbench.js`: 업로드, 범위 선택, 예비 점검, 심사 요청, 리뷰 파싱·근거 대조·보고서.
- `review_schema.py`: 6개 리뷰 범위·36개 평가 기준·공통 심사 지침.
- `review_ai.js`: 수동 키·선택 서버 연결, 범위별 실행·취소·재시도.
- `review_model.mjs`: 브라우저·서버 공통 모델 요청·응답 검증.
- `build_preview.py`: 기존 앱을 교체하지 않고 `preview/index.html`만 생성.
- `build_web.py`: 기본 `index.html`, 미리보기, 기존 장별 `chapters/index.html` 생성.
- `ui.html`, `reviewers.py`, `pdf_browser.js`: 기존 장별 도구와 공통 PDF 처리.

기존 Python API는 별도로 유지합니다. 설치는 `python -m venv .venv`, `.venv/bin/python -m pip install -r requirements.txt`, 실행은 `.venv/bin/python app.py --port 8000`입니다. `/health`, `/api/roles`, `/api/requests`, `/api/pdf`는 기존 API 경로이며 새 화면은 이 API를 호출하지 않습니다.

## 검증

```sh
.venv/bin/python -m unittest discover -s tests -v
PYTHONPATH=.:tests python tests/review_browser_smoke.py
PYTHONPATH=.:tests python tests/direct_ai_browser_smoke.py
PYTHONPATH=.:tests python tests/ai_browser_smoke.py
npm test
PYTHONPATH=. python tests/browser_smoke.py
```

브라우저 검증에는 별도 Playwright와 Chromium이 필요합니다. 실제 파일 선택·한글 PDF·페이지 범위·오류 시 원고 보존, 범위별 필터, 합성 리뷰 응답 가져오기, 인용 불일치, 원고 변경 후 응답 거부, HTML 주입 방지, 내보내기·작업 복원, 모바일·sandbox iframe을 검증합니다. 합성 자료를 사용하며 실제 논문·실제 AI 리뷰 품질은 검증하지 않았습니다.

`vendor/pdfjs/`는 공식 npm PDF.js 6.4.299를 SHA-512 무결성 검증 후 가져온 자료입니다. 라이선스와 무결성 정보가 포함됩니다.
