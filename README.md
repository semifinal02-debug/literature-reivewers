# 스마트 건설 로보틱스 논문 리뷰어

석·박사 논문을 위한 역할별 **검토 요청 생성기**입니다. 기술, 안전, 대응 대책, 작업계획을 중심으로 구성하며 자율주행은 제외합니다. AI 모델을 호출하지 않습니다. 생성한 요청문을 ChatGPT에 복사해 실제 검토를 실행합니다.

## GitHub에서 웹앱 열기

코드를 GitHub에 저장하는 것과 웹앱을 게시하는 것은 별개입니다. 저장소 파일 화면에서 `index.html`을 클릭하면 소스가 보입니다.

GitHub Pages로 게시하려면 저장소 **Settings → Pages**에서 **Deploy from a branch**, 브랜치 **main**, 폴더 **/(root)**를 선택하고 저장하세요. 완료되면 Pages 설정에 실제 사이트 주소가 표시됩니다. `index.html`에 필요한 자료가 포함되어 있어 Python API 서버나 Supabase 없이도 사용할 수 있습니다. `.nojekyll`도 포함했습니다. Pages 메뉴나 게시 옵션의 사용 가능 여부는 계정·저장소 정책에 따릅니다.

현재 구현은 사용자가 선택한 PDF와 원고를 브라우저 안에서 처리합니다. 실제 논문 자료나 인증 키를 GitHub 저장소에 업로드할 필요가 없습니다.

## 로컬 실행

PDF 추출과 장별 요청 생성은 **브라우저 안에서 실행**합니다. Python API 서버나 Supabase 연결이 없어도 정적 화면에서 사용할 수 있습니다. 실행에 필요한 PDF.js 모듈·글꼴·문자 매핑과 리뷰어 기준을 `index.html`에 포함했습니다. API 키는 필요 없습니다.

정적 웹 서버로 실행하려면:

```sh
cd /workspace/literature-reivewers
python -m http.server 8000 --bind 127.0.0.1
```

기존 Python API와 테스트도 유지합니다. 이 경로는 Python 3.12 및 `pypdf`를 사용합니다:

```sh
cd /workspace/literature-reivewers
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py --port 8000
```

브라우저 사용이 가능한 로컬 환경에서는 포트 8000으로 접속합니다. 서버는 루프백에만 바인딩됩니다. 특정 제품의 미리보기 연결 상태는 별도 확인이 필요합니다. 정적 서버와 API가 없는 sandbox iframe에서 브라우저 기능을 검증했습니다.

## 사용 순서

1. 공통 정보에서 논문 주제, 연구 질문, 목차, 학위 수준, 교수 피드백을 설정합니다. 미정인 정보는 비워둘 수 있습니다.
2. 왼쪽에서 1장 서론, 2장 문헌 검토, 3장 방법론, 4장 사례·결과, 5장 논의·결론을 선택하고 **해당 장 원고만** 입력합니다. 실제 목차가 다르면 공통 정보에 기재하세요. 원고를 붙여 넣거나 PDF 및 UTF-8 `.txt`/`.md` 파일을 업로드합니다.
3. 각 장의 6개 평가 기준과 권장 절 구성을 확인하고 안전·대책 및 기술·작업계획 심화 관점을 선택합니다. 해당 장만 생성하거나 원고를 입력한 모든 장의 요청을 따로 생성합니다. 요청을 복사하거나 Markdown으로 저장합니다.
4. ChatGPT에 요청을 붙여 넣습니다. 역할별로 새 대화에서 실행하면 검토 범위를 구분하기 쉽습니다.
5. 응답의 원문 인용을 실제 원고와 대조하고, 문헌·수치·제안의 정확성을 확인합니다. 수정한 원고로 다시 검토합니다.

각 장 원고는 브라우저 탭 안에서 독립적으로 유지됩니다. **작업 파일 저장/열기**로 원고와 공통 정보를 JSON 파일로 내보내고 복원할 수 있습니다. 파일에는 원고가 포함되므로 직접 보관하세요. 입력을 바꾸면 이전 생성 결과를 숨겨 오래된 요청을 사용하는 일을 줄입니다. 전체 생성 시 제공 범위 선택은 모든 선택 장에 공통 적용됩니다.

장별 출력은 절별 진단, C1~C6 기준 평가, 전용 분석표, 수정 우선순위, 실제 문단 수정안, 확인 질문으로 구성됩니다. 1장은 연구 논리 사슬과 질문 진단, 2장은 문헌 비교 매트릭스와 공백–근거 표를 필수로 요청합니다. 다른 장의 원고를 자동으로 혼합하지 않습니다. 전체 논문이 제공되지 않으면 전체 일관성 판단을 보류하도록 요청합니다. 문헌 목록만으로 해당 문헌의 내용이 검증되었다고 주장하지 않도록 요청합니다.

웹앱 없이 쓰려면 `docs/chapters/`의 장별 요청 템플릿을 사용하세요.

## PDF 업로드

선택한 장에서 **PDF·텍스트 업로드** 또는 그 아래의 실제 파일 선택 입력을 누릅니다. 진행 상태·완료·오류는 파일 선택 영역 바로 아래에 표시됩니다. 논문 전체 PDF라면 먼저 시작·끝 페이지를 입력하여 그 장만 추출하세요. 페이지 번호는 인쇄된 쪽 번호가 아니라 PDF 파일의 첫 페이지부터 세는 번호입니다. 범위를 비우면 PDF 전체를 추출합니다. 시작이나 끝만 지정할 수도 있습니다.

PDF는 최대 20MB이며 한 번에 100페이지, 본문 25만 자까지 추출합니다. 추출된 본문에 `[PDF 2페이지]`처럼 원본 위치를 표시합니다. 표·수식·다단 편집은 읽기 순서가 달라질 수 있으므로 원본과 대조하고 원고 칸에서 수정하세요. 장을 자동으로 구분하지 않으며 지정한 범위를 현재 선택한 장에 넣습니다.

텍스트가 없는 스캔본은 OCR이 필요하다는 안내를 표시합니다. 텍스트가 일부 페이지에만 있으면 누락 페이지를 알립니다. 암호화된 문서는 잠금이 해제된 사본이 필요합니다. 추출 실패 시 기존 원고를 유지합니다. 원본 PDF는 브라우저 메모리에서 처리하며 서버로 전송하거나 보관하지 않습니다. 현재 브라우저 화면은 Python API를 사용하지 않습니다.

## 자료 처리와 한계

- 앱은 원고를 자동으로 파일에 저장하거나 외부 서비스에 전송하지 않습니다. 브라우저 메모리에서 PDF와 요청문을 처리합니다.
- ChatGPT에 붙여 넣거나 다운로드한 파일의 보관·공유는 사용자가 결정합니다.
- 합성 예제는 흐름 시연용이며 실제 연구나 검증된 결과가 아닙니다.
- 생성물은 검토 요청입니다. 실제 AI 응답의 정확성과 학위 적합성을 보증하지 않습니다.
- OCR, 문헌 검색, API 호출, 다중 사용자 서비스는 제공하지 않습니다.

## 검증

```sh
.venv/bin/python -m unittest discover -s tests -v
```

서버 준비 확인은 `GET /health` (`pdf_import: true`), 역할 조회는 `GET /api/roles`, 요청 생성은 `POST /api/requests`를 사용합니다. PDF 업로드는 `POST /api/pdf?start=2&end=5`로 원본 바이트를 전송합니다 (`Content-Type: application/pdf`).

위 API는 기존 Python 경로용입니다. 현재 웹 화면은 해당 API가 없어도 동작합니다. 선택적으로 Playwright와 Chromium이 설치된 Python 환경에서 실제 브라우저 회귀 검증을 실행할 수 있습니다:

```sh
PYTHONPATH=. python tests/browser_smoke.py
```

검증 내용: 실제 파일 선택 버튼, 한글 PDF, 페이지 범위, 장별 원고 구분, 브라우저·Python 요청문 일치, 오류 표시와 원고 보존, API 요청 없음, 모바일 너비, sandbox iframe.

## 화면 수정과 빌드

`ui.html`은 화면 원본, `pdf_browser.js`는 브라우저 PDF 처리와 요청 생성 코드입니다. `reviewers.py`가 장별 평가 기준의 기준 소스입니다. 이 파일들을 수정한 뒤 `python build_web.py`로 `index.html`을 생성합니다. 완성된 `index.html`과 vendored PDF.js 자료는 저장소에 포함하며, 정상 실행 시 다시 다운로드하거나 빌드할 필요가 없습니다.

`vendor/pdfjs/`는 공식 npm의 PDF.js 6.4.299를 SHA-512 무결성 검증 후 가져온 자료입니다. 라이선스와 무결성 정보도 포함합니다. Supabase 연결·원본 PDF 저장은 구현되지 않았습니다.
