# 스마트 건설 로보틱스 맞춤 논문 리뷰어 구축 계획

## 현재 구현: 범위별 심사 워크스페이스

논문 업로드 후 연구 공백·방법론·결과를 별도로 평가하고, 사례·안전·작업계획을 추가하는 화면을 기본 앱으로 제공한다. 각 범위는 6개 기준을 갖는다. 장 번호는 기본 논문 구성에 대한 안내이며 사용자가 제공한 장·절과 실제 목차를 우선한다. 기존 장별 도구도 `/chapters/`에 보존한다.

사용자가 선택한 ChatGPT 복사 방식을 유지한다. 평가 기준·프로필·줄 번호가 포함된 요청을 ChatGPT에 보내 실제 리뷰를 실행하고, JSON 응답을 앱으로 가져오면 범위별 평가, Major/Minor 의견, 수정 행동, 결과 지표, 확인 질문을 보고서로 만든다. 원문 인용의 문자열·줄 위치를 대조하고 일치하지 않는 인용을 표시한다. 입력 ID 불일치는 가져오기를 거부하며 누락된 기준은 판단 보류로 표시한다. 이 대조는 리뷰어 해석의 학술적 검증을 대체하지 않는다.

통계적 근거, 효과 크기·불확실성, 기술 성능, 현장·실무 의미를 구분하고 종합 점수를 만들지 않는다. 정성 연구에 통계 검정을 일률적으로 요구하지 않는다. 앱의 자동 예비 점검은 규칙 기반 문구 탐지로 한정하며 학술적 타당성은 판단 보류로 표시한다.

검증은 합성 PDF와 합성 리뷰 응답으로 수행한다. 실제 원고에 대한 실제 모델 리뷰와 맞춤 기준의 효과 비교는 다음 단계이며 완료로 주장하지 않는다. 직접 API 호출·외부 문헌 검색·OCR·클라우드 원고 저장은 구현 범위에 포함하지 않았다. 수정본은 `/preview/`에 먼저 게시하고 기본 화면에 반영한다.

## 목적과 범위
스마트 건설의 로보틱스 연구를 대상으로 석·박사 논문 원고의 논리, 선행연구 근거, 방법론과 사례 분석을 검토하는 도구를 만든다. 논문을 자동 작성하거나 학위 수준을 보증하는 도구가 아니라, 연구자가 검토하고 수정할 수 있는 근거 중심 피드백을 제공한다.

확정된 조건: 스마트 건설, 로보틱스 중심, 석·박사 논문 수준. 자율주행은 연구 범위에서 제외하며 기술, 안전, 대응 대책, 작업계획에 초점을 둔다.
미확정 조건: 연구 질문, 논문 목차, 학위 구분, 데이터, 세부 로봇 분야, 제출 기한.
첫 시연 시나리오: 건설 로봇의 작업 기술, 위험 요인, 대응 대책과 작업계획의 연결을 검토한다. 사례 비교는 리뷰 기능이며 실제 논문 방법론으로 확정하지 않는다.

## 리뷰어 설계
장별 입력과 평가를 분리한다. 1~5장의 번호는 기본 구성이고 실제 논문 목차를 우선한다. 각 장은 6개 전용 평가 기준과 2개의 필수 분석표를 갖는다. 안전·대책 및 기술·작업계획은 각 장에 추가할 심화 관점이다. 일부 발췌에서 누락된 내용을 전체 장의 결함으로 판정하지 않는다.
| 역할 | 평가 기준 | 분야별 확인 사항 |
|---|---|---|
| 1장: 서론 | 문제 정의, 연구 질문, 범위, 기여의 연결 | 건설 현장 제약과 로봇 활용 필요성을 증거로 설명하는가 |
| 2장: 문헌 검토 | 검색·선정 기준, 연구 분류, 비판적 종합, 연구 공백 | 작업·기술·안전·대책·작업계획·현장 적용 수준을 구분하는가 |
| 방법론 | 연구 질문과 방법의 적합성, 재현성, 타당성 위협 | 시뮬레이션·실험·현장 검증을 구분하고 비교 조건을 명시하는가 |
| 케이스스터디 | 사례 선정, 공통 비교 기준, 자료 출처, 일반화 한계 | 생산성·품질·안전·비용·현장 통합을 자료가 있는 범위에서 평가하는가 |
| 통합 | 장간 논리, 용어 일관성, 주장 범위, 기여 | 실험실 성능을 현장 성과로 과장하거나 상관관계를 인과로 해석하는가 |
| 안전·대책 | 위험 식별, 노출 조건, 저감 대책, 잔여 위험 | 작업자와 로봇의 접촉, 낙하물, 장비 고장, 비상 대응을 근거로 평가하는가 |
| 기술·작업계획 | 작업 분해, 선후 관계, 자원·공간 제약, 예외 처리 | 로봇의 능력과 현장 제약이 작업 배치 및 실패 대응에 반영되는가 |

석사 평가에서는 명확한 질문, 적합한 방법, 근거 있는 결과를 중점 검토한다. 박사 평가에서는 독창적 기여의 주장과 근거, 기존 접근과의 차이, 타당성 및 일반화 범위를 추가 검토한다. 최종 기준은 소속 학과 지침과 지도교수 요구를 우선한다.

## 입력과 출력
입력: 논문 프로필(주제·질문·목차·학위 수준), 원고 텍스트, PDF, 제공 문헌, 교수 피드백. PDF는 브라우저에서 선택 페이지의 텍스트를 장별 입력으로 가져오며 원본 페이지 번호를 표시한다. 정적 화면에서도 PDF 처리용 서버 없이 추출하며 진행 상태와 실패를 파일 선택 영역에 표시한다. 원본과 추출 내용을 대조하고 수정할 수 있다. OCR과 문헌 자동 검색은 후속 기능이다.

출력: 검토 위치, 원문 인용, 문제 설명, 중요도, 수정 제안, 확인할 근거, 검토 불가 항목. 원문 인용은 입력과 일치해야 한다. 문헌의 존재·내용·최신성은 제공 자료나 실제 검색으로 확인한 경우에만 확정적으로 기술한다. 검토하지 못한 내용은 명시한다. 자료가 부족하면 점수 대신 판단 보류와 필요한 자료를 제공한다.

## 구현 순서
1. 분야별 평가 기준과 공통 결과 형식을 JSON으로 정의하고 역할별 프롬프트를 만든다.
2. 텍스트 입력 → 프로필 설정 → 역할 선택 → 리뷰 실행 → 결과 내보내기의 최소 웹앱을 구현한다.
3. 모델 연결을 분리한다. 모델 제공자와 사용 가능한 인증을 확인한 후 실제 API를 연결한다. API 없는 시연은 UI 검증용으로 명확히 표시하며 실제 리뷰로 제시하지 않는다.
4. 사용자 원고 일부로 실제 리뷰를 실행한다. 원고가 없으면 합성 예제를 명확히 표시하여 흐름을 검증하고 실제 논문 검증은 미완료로 기록한다.
5. 일반 리뷰 프롬프트와 맞춤 프롬프트를 같은 원고·모델·조건에서 비교하고 원문 근거의 정확성, 제안의 구체성, 실행 가능성, 근거 없는 지적을 사람이 평가한다.

## 필수 검증
- 각 리뷰어가 자신의 범위에 맞는 피드백을 제공하는지 확인한다.
- 원문 인용과 입력의 일치, 제공하지 않은 참고문헌의 생성 여부를 검사한다.
- 빈 입력, 자료 부족, 모델 호출 실패를 사용자에게 정확히 표시한다.
- 실제 모델 요청과 응답 처리, 결과 내보내기를 검증한다.
- 시연·모의 결과와 실제 모델 결과를 구분한다.

## 제출물
맞춤 설계 계획서, 역할별 지침과 평가 기준, 실행 가능한 시제품, 입력·검토 결과 예시, 비교 평가와 한계 보고서.

## 다음 실행에 필요한 정보
세부 연구 방향과 검토할 원고 또는 초록. 실제 모델 연결 단계에서는 사용할 모델 제공자와 사용 가능한 환경 인증을 확인한다. 비밀 키는 채팅이나 저장소에 기록하지 않는다.
