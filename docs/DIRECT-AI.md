# 앱에서 직접 AI 리뷰 실행

현재 변경은 [미리보기](https://semifinal02-debug.github.io/literature-reivewers/preview/)에 적용한다. 기본 `index.html`은 기존 ChatGPT 복사 방식으로 유지한다.

## API 키를 직접 넣어 사용

1. 미리보기에서 PDF를 선택하고 추출 본문·연구 설정을 확인한다. 필요한 장이나 페이지부터 사용할 수 있다.
2. 연구 공백, 방법론, 결과, 사례, 안전, 기술·작업계획 중 필요한 범위를 선택한다.
3. **AI 리뷰 실행**에서 기본 연결 방식 **OpenAI API 키 직접 입력**을 사용한다. [OpenAI에서 발급한 키](https://platform.openai.com/api-keys)를 **OpenAI API 키** 칸에 입력한다. 키를 채팅·GitHub 파일에 넣지 않는다.
4. **GPT-4.1** 또는 **GPT-4.1 mini**를 선택하고 **연결 확인**을 누른다. 연결 확인은 원고 없이 선택 모델의 접근 권한만 확인한다. 제한된 권한의 키에는 Models 읽기와 Responses 쓰기 권한이 필요하다.
5. **선택 범위 분석 시작**을 누른다. 범위별 심사가 끝나면 원문 인용과 Major/Minor 의견이 포함된 보고서가 열린다. 분석 시작 때도 연결을 확인하므로 별도 확인 버튼은 선택 사항이다.

Vercel·Supabase·별도 서버 배포는 필요하지 않다. 브라우저에서 `https://api.openai.com/v1/models/{model}`과 `https://api.openai.com/v1/responses`로만 키를 전송한다. 직접 방식에서는 입력한 서버 주소를 사용하지 않는다. API 요금과 사용 한도는 ChatGPT 구독과 별도다. 키 오류·크레딧 부족·네트워크 차단은 화면에 안내하며 가짜 리뷰로 대체하지 않는다.

키는 현재 탭의 비밀번호 입력칸과 진행 중인 요청에서만 사용한다. 앱은 키를 브라우저 저장소·작업 파일·내보내기·URL·로그에 기록하지 않는다. 새로고침·페이지 이동 시 지워지며 **키 비우기**로도 삭제한다. 자동 저장이나 키 기억 기능은 없다.

## 리뷰가 실패할 때

연결 확인은 키·모델 접근만 확인한다. 생성 요청의 사용 예산·크레딧·토큰 한도를 보증하지 않는다. HTTP 429에서 알려진 원인 코드만 읽어 안내하며 제공자가 보낸 오류 원문은 표시·기록하지 않는다.

- `insufficient_quota`: API 크레딧이 없거나 예산 한도에 도달했다. 반복 실행으로 해결되지 않는다. ChatGPT 구독과 API 크레딧은 별도다.
- `rate_limit_exceeded`: 분당 요청량 또는 토큰 한도다. 기다렸다 재시도하고, 계속 제한되면 필요한 장·페이지와 한 범위부터 실행한다.
- 코드가 없거나 알 수 없으면 원인 미확인으로 안내한다. 크레딧 부족이라고 단정하지 않는다.

첫 생성 요청이 제한되면 나머지 범위는 **미실행**으로 표시하고 추가 요청을 보내지 않는다. 완료된 응답이 하나도 없으면 보고서가 있다고 안내하지 않는다. **현재 원고로 ChatGPT 요청 만들기**는 API 호출 없이 요청을 만들며, ChatGPT 응답을 가져오면 같은 범위별 보고서로 정리한다. 이 경로는 추가 API 비용이 없고 ChatGPT 계정의 이용 한도는 적용된다. 앱 안의 자동 AI 분석에는 사용 가능한 API 계정이 필요하다.

## 별도 서버 연결 (선택 사항)

API 키를 서버에 두고 앱 접속 암호로 사용할 경우에만 아래 Vercel 구성을 사용한다. 앱의 **연결 방식**을 **별도 AI 서버 연결**로 바꾸어 사용한다.

1. [Vercel 프로젝트 가져오기](https://vercel.com/new)에서 GitHub 저장소 `semifinal02-debug/literature-reivewers`를 선택한다. 별도 프로젝트로 만들면 기존 GitHub Pages 주소를 유지할 수 있다.
2. Framework는 **Other**, Root Directory는 저장소 루트로 둔다. 저장소의 `vercel.json`이 `npm run build`와 Output Directory `preview`를 지정한다. HTML은 미리 빌드되어 있으므로 Vercel에서 Python이나 PDF 도구를 설치하지 않는다. Node.js 22 이상을 사용한다.
3. Environment Variables에 다음 값을 등록한다. 키와 접속 암호는 Vercel의 서버 환경 변수에만 넣고 GitHub·채팅·HTML에는 넣지 않는다.
   - `REVIEWER_API_KEY`: [OpenAI API 계정에서 발급한 키](https://platform.openai.com/api-keys). ChatGPT 구독과 API 사용은 별도이며 API 계정의 크레딧·사용 한도가 적용된다.
   - `REVIEWER_ACCESS_TOKEN`: 이 앱의 접속 암호. 길고 추측하기 어려운 값을 직접 정한다. 브라우저에는 API 키 대신 이 암호를 입력한다.
   - `REVIEWER_MODEL`: `gpt-4.1`. Responses API와 Structured Outputs를 지원하며 해당 계정에서 접근 가능한 모델을 사용한다.
4. Deploy를 실행한다. Vercel이 실제 배포 주소를 표시한 뒤 그 주소를 사용한다. 이 문서는 배포가 완료되었다고 주장하지 않는다. 키 변경 후에는 재배포한다.

배포한 Vercel 주소에서 앱을 열면 API가 같은 서비스에 있으므로 **AI 서비스 주소**를 비워두고 앱 접속 암호를 입력한다. GitHub Pages 미리보기에서는 실제 Vercel 배포 주소의 도메인을 **AI 서비스 주소**에 넣는다. 주소에는 `/api` 경로·쿼리·암호를 넣지 않는다.

공개 미리보기 URL에 Vercel 자체의 Deployment Protection이 적용되어 있으면 먼저 Vercel에서 접근 권한을 설정해야 한다. GitHub Pages에서 호출할 서버는 사용자에게 접근 가능한 배포 주소가 필요하다. 앱의 API는 별도로 접속 암호를 확인한다. 배포 플랫폼의 함수 실행 시간이 180초 설정을 지원하지 않으면 계정의 지원 범위에 맞게 조정하고 원고 범위를 줄인다.

외부 프런트엔드 주소가 달라지면 `REVIEWER_ALLOWED_ORIGINS`에 정확한 origin을 쉼표로 구분해 등록한다. 기본값은 `https://semifinal02-debug.github.io`이며 같은 Vercel origin도 허용한다. 와일드카드는 사용하지 않는다.

## 앱에서 사용

PDF를 업로드하고 연구 설정·범위를 선택한 뒤 **AI 리뷰 실행**을 누른다. 기본 방식에서는 자신의 OpenAI API 키를 입력한다. 선택한 서버 방식에서는 서버 주소·앱 접속 암호를 입력한다. 심사자는 선택 범위를 하나씩 평가한다. 한 범위당 생성 요청 1회이며 완료된 범위와 진행 상태가 표시된다.

결과는 범위별 6개 기준, Major/Minor 의견, 정확한 원문 인용, 수정 행동, 결과 지표의 네 축, 확인 질문과 한계로 정리한다. 완료된 응답의 인용을 원고 줄과 대조하며 이 확인은 판단의 학술적 타당성을 보증하지 않는다. 일부 범위가 실패하면 완료된 보고서를 보존하고 **실패한 범위만 다시 실행**할 수 있다. 원고·설정을 바꾸면 진행 중인 요청을 취소하고 이전 원고의 응답을 표시하지 않는다. 취소 전에 제공자가 모델 요청을 처리한 경우 API 사용이 이미 발생했을 수 있다.

원고는 최대 25만 자다. 전체 논문도 제공할 수 있지만 같은 원고를 각 선택 범위에 보내므로 요청 규모와 요금이 커질 수 있다. 필요한 장·페이지부터 검토하면 문맥과 근거를 확인하기 쉽다. 앱은 본문을 자동으로 잘라 일부만 검토하지 않는다.

## 자료 처리

PDF 원본은 브라우저에서 읽으며 **분석 시작 시 추출한 본문·연구 설정·평가 기준만** OpenAI에 보낸다. 서버 방식에서는 연결한 서버도 경유한다. 서버는 원고를 파일에 저장하지 않으며 원고·키·모델 응답을 로그로 출력하지 않는다. OpenAI 요청에는 `store: false`를 사용한다. 제공자의 별도 데이터 처리·보관 정책은 해당 API 계정 설정을 확인한다.

직접 방식의 API 키와 서버 방식의 앱 접속 암호는 현재 탭에서만 사용한다. 서버 방식의 제공자 키는 서버 환경 변수에서 읽는다. **작업 저장** 파일에는 원고와 AI 리뷰가 포함되며 연결 키·접속 암호는 포함하지 않는다. 저장 파일의 `ai.model`은 모델명 표시용 메타데이터이며 응답의 진위를 증명하는 서명이 아니다.

외부 문헌 검색·OCR·원자료 통계 재검정은 수행하지 않는다. 원고에 없는 값·문헌·근거를 만들지 않도록 지시하고, 자료 부족은 판단 보류로 표시한다. 모델 응답의 해석·수치·문헌은 연구자가 확인해야 한다.

## 개발 환경

현재 클라우드에는 Node.js가 설치되어 있으며 외부 npm 의존성은 없다. 코드 수정 뒤 `python build_preview.py`로 미리보기와 공통 계약 JSON만 생성한다. `python build_web.py`는 기본 앱도 교체하므로 사용자 확인 전에는 실행하지 않는다.

```sh
npm ci --ignore-scripts --cache /workspace/.npm-cache
NODE_USE_ENV_PROXY=1 npm start
```

서버는 루프백에만 바인딩한다. 이미 사용 중인 포트가 있으면 `REVIEWER_PORT`로 빈 포트를 지정한다. `.env`를 자동으로 읽지 않는다. 로컬 파일을 사용하는 경우 Node 22 이상에서 `node --env-file=.env server/dev.mjs`로 실행한다. 실제 비밀 값은 저장소에 넣지 않는다. 클라우드에서 proxy secret을 사용하면 `NODE_USE_ENV_PROXY=1`로 지원되는 프록시 경로를 사용한다. 클라우드 실행 환경을 직접 공개 웹 호스팅으로 취급하지 않는다.

`GET /api/status`는 키 값 없이 설정·접속 상태를 반환한다. 루프백에서 같은 origin으로 개발할 때는 앱 접속 암호를 생략할 수 있으며 공개 Vercel 서버에는 접속 암호가 필수다. `POST /api/review`는 JSON 본문과 `Authorization: Bearer <앱 접속 암호>`를 받는다. 입력 모델명·업스트림 주소를 받지 않고 서버에서 고정한 OpenAI 주소와 설정 모델만 사용한다.

## 검증과 남은 단계

```sh
npm test
PYTHONPATH=.:tests python tests/direct_ai_browser_smoke.py
PYTHONPATH=.:tests python tests/ai_browser_smoke.py
PYTHONPATH=.:tests python tests/review_browser_smoke.py
.venv/bin/python -m unittest discover -s tests -v
```

합성 제공자 응답으로 정적 브라우저→OpenAI 요청 형식, 키 입력·비우기·새로고침, 고정 목적지, 저장소·내보내기 비밀 미포함, 한도 오류 시 후속 호출 중지, 6개 범위, 부분 실패·재시도·취소, 작업 복원, 모바일을 검증한다. 선택 서버 방식의 실제 API 핸들러도 인증·CORS·오류·원고 변경으로 검증한다. 합성 제공자는 테스트에서만 주입하며 제품에서 가짜 모델을 선택할 수 없다.

OpenAI 공식 API의 GET·POST 사전 요청은 GitHub Pages origin에서 HTTP 200과 브라우저 직접 호출 허용 헤더를 반환했고 키 없는 모델 조회는 읽을 수 있는 HTTP 401을 반환했다. 실제 키가 없으므로 인증된 생성 호출·학술 리뷰 품질은 검증하지 않았다. 사용자는 웹에서 자신의 키를 입력하고 합성 예시로 먼저 실행한 뒤 논문을 검토할 수 있다. Vercel 배포는 직접 방식의 선행 조건이 아니다.
